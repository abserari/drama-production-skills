## 一、 核心架构决策记录 (ADR)

### ADR-01: 音频生产路线——为什么放弃纯 TTS 方案回归 H3 原生一体音轨？
- **背景**：v3.4 曾建立以 CosyVoice2 为核心的“音画分流”路线（H3 仅出画面与口型参考，音频全靠后期 TTS 克隆 + 点状拟音拼接）。
- **实测裁决（《钟楼救援》多轮比对）**：
  - CosyVoice 三版对比（zero_shot / instruct2 焦急 / instruct2 沉稳）直观听感均明显劣于 H3 原生直出。
  - **核心根因**：H3 是视音频多模态联合扩散模型（AV-DiT），生成时看着画面一体演进，台词口型、气息、情绪张力与动作节奏天然对齐；而后贴 TTS 存在“对位估算误差 + 参考音色干瘪 + 0.5B 情感指令飘忽”三层不可逆损耗。
- **决策结论**：
  1. H3 原生音轨重新确立为成片交付主体；
  2. CosyVoice2 降级为备用兜底（仅在 H3 台词严重吞字且重抽无法解决时介入）；
  3. 交付主路径采用 `concat` 视频无损流复制（copy）+ 原生三轨交付，利用低电平环境床音（`assets/amb/`）掩盖段间微小切断感；
  4. 引入 FFmpeg 动态侧链压限（`sidechaincompress`）实现对话时 BGM 自动避让（-14dB Ducking）。

### ADR-02: 续接策略转型——为什么从“承接式”转向“续接只传状态，不传叙事”？
- **背景**：早期续接尝试使用“承接式”写法，即在提示词中要求下一段开头好几秒延续上一段的动作与机位，导致观众感知“接缝过大、画面卡顿僵死”。
- **实测发现（《锈海拾荒》17 段端到端验证）**：
  - 续接钉帧（5 帧）确实复现了上一段尾帧，但 AI 难以在长达数秒的延展区内保持上一段的完全动力学惯性，任何微小的光影或姿态偏差都在这几秒内暴露无遗。
- **决策结论**：
  1. **续接只传状态，不传叙事**：在提示词中不再体现续接关系，第 1 拍直接写新镜头（新机位、新景别、新动作），该切镜就切；
  2. 借钉帧锁定**人物站位、朝向、道具归属、主光源色**的跨段连续性；
  3. `concat` 自动裁头机制精准裁去这 5 帧钉帧。观众看到的接缝 =「上一段尾帧 → 新镜头第一帧」的干净硬切，**硬切天然不可疑，接缝彻底消失在镜头语言里**。

### ADR-03: 质检体系升级——为什么引入五级定量闸门与黄金集回归闭环？
- **背景**：早期仅依靠人工“看 8 格联络图”，不仅效率低，且尾部假动作（tail_motion 伪移动）和字幕漏字无法稳定拦截。后来增加了定量脚本，但调参时常常“修好 A 却破坏了 B”。
- **决策结论**：
  1. **建立五级递进闸门**：
     - G1 静态提示词规范检查（preflight）；
     - G2 运行态与环境检查（GPU 显存防暴雷、工作流指纹一致性）；
     - G3 自动化定量快检（流完整性、光流能量、台词 ASR 纯净度）；
     - G4 人工视觉签字（逐拍核对 beat sheet、关键帧身份一致性）；
     - G5 成片接缝与交付验收。
  2. **建立金样本（Golden Set）考题库与回归机制**：
     - 将每次误报或漏报的真实案例（帧图、光流特征、人工期望）固化到 `golden/cases/<id>`；
     - 检测器做任何参数或阈值调整，必须先执行 `python golden.py run`，五类判定（pass / fixed / tolerant / still-wrong / REGRESSED）中**一旦出现新回归错法（REGRESSED），严禁合入**。

### ADR-04: 提示词排布铁律——为什么台词必须排在文本最前面？
- **背景**：大量段落出现“台词被顶到段末（speech_end ≥ 9s）”甚至直接吞字的问题，换 seed 多次仍然无法解决。
- **实测根因**：H3 对文本是时序敏感的。若将动作描述放在台词前，模型必定等动作演完才开始说对白。
- **实测梯度数据**（175 帧 / 7.29s 短片段）：
  - 文本排在动作串之后：**完全没开口（语声 0 个，整段无对白）**；
  - 文本排在第 3 拍最前：**7.07s 说完（离段末仅差 0.23s，吞字边缘）**；
  - 文本排在第 2 拍最前：**6.64s 说完（离段末 0.65s，风险较高）**；
  - 文本排在第 1 拍最前面：**5.09s 说完（距段末留白 2.21s，完美 PASS）**。
- **决策结论**：
  1. **铁律：一段一句对白，必须紧跟 `<Subject>` 写在文本最前，动作描述整块后置于 `<d>` 标签之后**；
  2. 带有表演词（如哭腔、语速快而碎、字尾黏连）时，台词物理时长会拉长至通常语速的 **1.7 倍**，必须留足对应预算；
  3. 台词块位置调整后，重抽计数清零（因提示词已实质变动）。

### ADR-05: 算力与画质边界——为什么严禁减步数提速与警惕 VAE 瓶颈？
- **背景**：为提高单段生成速度，社区曾尝试将采样步数从 20 步压缩到 10 步，或使用激进缓存。
- **实测与决策**：
  1. **严禁减步提速**：20→10 步虽然画面轮廓损伤较小，但**高频音频信号严重失真破碎**。短剧是有声短剧，任何加速方案必须音画独立验收；
  2. **认识 VAE 物理瓶颈**：人脸与文字在 VAE 编解码环节就已经存在信息损耗，后期的 Real-ESRGAN / Waifu2x 等超分模型只能锐化边缘，无法凭空“脑补”已被抹平的五官特征。因此面部精度必须在采样侧与参考图侧通过高分辨率和 FaceRefine 解决，不在交付端死磕；
  3. **段间色彩漂移是物理现实**：由于各段独立解码，色彩与曝光的微弱漂移不可避免，需通过前置风格母版与统一后处理曲线进行收敛。

### ADR-06: 模块化解耦——为什么从单体 Skill 拆分为多工序专业技能栈？
- **背景**：v3.x 时代的 `comfy-h3-video-producer` 是一个 93KB 的全功能单体巨石，包含编剧、分镜、首帧、提示词编写、工作流执行、音频后处理、质检等多重职责，导致大模型在多轮交互中上下文极易膨胀超载。
- **决策结论**：
  1. 参考现代工业化短剧生产流水线，拆解为 8 个高内聚、低耦合的专业工序技能：
     - `drama-production-director`（总制片与协调调度）
     - `drama-director-staging`（导演分镜与视觉节奏规划）
     - `drama-keyframe-forge`（首帧渲染与视觉资产锚定）
     - `comfy-h3-render-core`（H3 物理渲染执行工序）
     - `drama-audio-soundstage`（音效、配乐与侧链声场工程）
     - `drama-finishing-upscaler`（拼接、调色与 4K 超分交付）
     - `drama-production-review`（全流程独立质检与防线把关）
     - `comfy-h3-video-producer`（单技能直通旧版兼容层）
  2. 原版单体详尽规约归档至参考文档，新技能各司其职，保证生产线可在任意环节人工切入、替换工具或并行作业。

## 二、 实战踩坑与调优梯度实测表

| 故障现象 | 根因剖析 | 黄金排查解法 |
|---|---|---|
| **台词被顶到段末切断** | 台词块被写在动作串后面，模型等动作演完才说 | 严格把 `<Audio 1>...说：<d>...</d>` 挪到第 1 拍最开头，动作移至对白之后。 |
| **画面中人物不动，变幻 PPT** | 缺乏足够的动态关键词，或提示词写了否定式静止约束 | 严禁使用“静止不动/站立无言”等负向词；加入摄影机运动或肢体微动指示。 |
| **续接段组装后画面缺失 5 帧** | 误读了 `trim_frames` 字段 | 拼接裁头只认台账 `cont.frames`（cont off 必须记 0）。 |
| **面部五官模糊或崩坏** | VAE 压缩极限或参考图比例不当 | 确保参考图严格 16:9，面部占比符合景别要求；使用专用远景修脸工作流。 |
| **背景音乐盖过人声** | 直接全局固定音量混合 | 严禁直接叠加；强制使用 `cinematic_audio_mixer.py` 走侧链压限 ducking 处理。 |
| **两段音色不一致、飘忽不定** | 每次使用不同音色或依赖纯文字生成 | 实施原生自锚定（Self-Anchor Voice），从第 1 段提取真实生成的对白作为全片参考。 |

## 2026-11-07：分区反馈与独立动作工序
- 背景：360p试制后，用户指出句前笑、动作拆解不足和节奏偏慢；要求合并同事v3.15.2资料，动作参考研究延后，本轮先发布。
- 证据：用户观看反馈是本轮创作取向依据；工具与闸门51项测试通过。尚无新动作路线、去笑声或1.3x修订的实片效果证明。
- 决策：对白自然度归声音工序；打斗独立为drama-action-production，后续以网络参考拆解动作/机位/切点，H3不是强制渲染器；运镜资料归导演；倍速只作项目试剪参照。新规则不追认旧片通过。
- 不变量：保留原子台账、输入/产物哈希、回执核对、首帧约束、任务级中断及版本验收。技能源仍在skills/，仓库内与工作区发布副本同步。
- 未采用：整包覆盖宿主路径/声线、重试耗尽改PASS、全局清队列、超时捡最新终片、用ASR代替听审、把动作模型换代当作拆解问题的默认解法。保留同事原资料供对照，当前规则优先。
