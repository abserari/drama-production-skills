# 动作戏制作工序

## 输入与前置检查
读取已批准剧情、人物与道具身份、场景空间、动作胜负与后果、预算和交付规格。确认双方初始位置、惯用手/持械侧、接触位置、运动方向和可用工作流。缺关键动作依据先补动作分镜/关键帧；不能把普通对白模板直接改成“激烈打斗”。

## SOP 与已有工具
1. 将每个交锋拆为意图/预备→攻击轨迹→接触或躲避→受力反馈→落位；每镜只承担可读的动作单元，保留同一空间轴线、道具持有和下镜起态。接触不成立时，音效/快切不能假造“动作已通过”。
2. 输出动作分镜与起止状态，有需要时交给 drama-keyframe-forge 制作关键帧。按 [选路与试片](references/route-selection.md) 分别评估 H3 动作配方、其他已安装模型/工作流、现有素材剪辑。不假定任何模型已可用；不为换模型自动下载大型权重或接入新付费服务。
3. 先做一轮低清可判读动作试片，再激活路线；默认遵守项目360p测试限制。H3 路径使用现有渲染技能，其他路径直接用其已有工具，交接仍保留提交回执、实际图、输入参数指纹与文件哈希。不建立通用适配框架。
4. 审查完整动态，在接触/反转处加密抽帧：攻击者与承受者是不是正确的人、手/刃数量、刃的侧别、距离与速度、格挡接触、穿模、重量/惯性、受击结果和连续性。对话与战斗拆开处理，避免同时要求复杂打斗和长对白。独立拟音/撞击声交给声音工序对准真实接触帧。
5. 只将通过的一采送精修；未选择精修则交付本轮测试版。与普通对话镜头分别收片，最后按版本剪辑合并。

## 输出与完成证据
项目内动作分镜、所选 route/model/workflow_version、实际工具与参数、输入/产物哈希、任务编号、动作检查与选路对照记录。只给真实交接定义字段；可沿用 plan 每镜条目增加 production_route、action_beats 和 checks。
每个交锋都必须动态审查，不使用普通镜头20%抽样替代接触检查。静态首帧好看、光流分数高、ASR通过不证明打斗成立。无动态观看能力则 needs_review。

## 失败、替换与约束
错误只返工当前交锋及依赖落位的相邻镜，保留已通过对白。最多两轮质量返工；无改善停止该配方自动重抽，标记待验或按已授权替换流程试用别路，不能把耗尽当通过。H3 动作专线与其他模型目前均是可试路径，不能宣布已验证优于旧版。
