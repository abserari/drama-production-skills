# 独立制作审查

## 适用条件
可以由原 agent、独立 agent 或人工执行。角色独立指使用独立证据与标准，不保证必须拥有子 agent 工具。纯文本项目同样适用。

## 输入与前置检查
读取项目目标、检查对象、验收标准、产物实际内容及对应哈希；不要只读制作者的总结。缺文件、缺标准或无法观察内容，结论为 needs_review/blocked，不输出通过。

## SOP
1. 先逐一核对 plan.required 工序的 outputs 是否真实存在、内容是否对应本次目标，审查文件也必须实际落盘；不要只接受制作方 result.json 的通过声明。确认检查类型：物理完整性、内容匹配、连续性、声音、审美或交付完整性。按项目要求选择，不为纯剧本调用视频检查。
2. 首次风格和代表性样本由用户定调。新角色、场景、技能版本必检；其余按 [抽样与证据](references/review-protocol.md) 选取。
3. 先运行适用的现有检查工具，再查看文本、图片或听看片段。ASR 通过不证明口型或人物正确，分辨率合格不证明画质合格。
4. 保存结构化结论到 checks/，使用 [审查模板](assets/review-template.json)。非阻塞检查允许无关工序继续；命中项目硬性条件仍阻止交付。
5. 给出具体问题位置、证据和最小返工范围。比较下一轮 fixed、residual、new_issues，不能用综合分掩盖关键失败。

## 输出与完成证据
review_id、stage_id、artifact_sha256、reviewer_kind、mode、status、criteria、evidence、issues、next_action。状态为 passed/failed/needs_review/blocked。评审描述必须与实际可见证据一致。
人工确认的 reviewer_kind=human 只能引用真实用户输入；agent 自己的判断标记 agent。多个评审分歧保留原始结论，交给项目指定裁决者。

## 失败与恢复
对象改变则旧审查失效。抽样失败扩大到同角色/场景/技能版本批次。质量返工最多两轮，连续无改善停止自动返工；程序检查错误与内容失败分别报告。

## 可替换部分与约束
可更换评审模型、风格评价方法和抽样比例，需记录策略版本；硬性标准与用户批准的目标不能私自降低。审查者只写自己的结果文件，由协调者汇总台账。
