# 依据原作事件改写成短剧

适用：用户要求临摹实际游戏/原作剧情、忠实改编，或否决了自由创作的剧情。

1. 先明确忠实范围：事件顺序、人物动机/关系、对白意图与世界设定。默认不把“短剧节奏”当成额外添加袭击、打斗、身份反转或威胁的授权。
2. 优先检查实际原作脚本、任务日志、完整实录或可读截图；Wiki/攻略帮助定位与交叉核对，不能仅靠剧情摘要编出所谓原对话。来源不可见时记为未知，不伪称已核对。
3. 记录版本、首周目/重复游玩、任务阶段、玩家选项与分支。复玩缩略对白、后段事件、不同路线不能混作开场连续事件。使用恢复剧情的模组实录时标明该来源上下文，不冒称直接读取了未修改游戏文件。
4. 在项目创建事件账本：event_id、发生顺序、对白意图、图/录像时间码/脚本位置、证据文件及来源。将拟定镜头逐项映射事件；没有依据的新增动作/机位与新增剧情分别标注。
5. 对白用自己的措辞转成目标语言可演的场景，保留关系与性格。熟人挤兑和照顾不能都改成威吓；劝退后提供帮助的转折不能被“强冲突模板”抹去。不要复制整段原文或声称自写对白是官方台词。
6. 加快节奏优先压缩菜单、停顿、重复解释和分支展示；需要合并时间或搬动冲突时说明改编幅度并按项目人审策略确认。不能为了填满固定帧数扩写台词，也不能为了省资产改掉关键剧情。
7. 重新审查五项：事件顺序、动机、关系、分支一致性、动作/台词因果。保存原作依据、改写稿、差异与批准范围；被否决的旧稿归档，不覆盖证据。
8. 技术试片仅使用独立批准的片段时，应与整集稿分别授权。改剧本不必丢弃已批准技术试验，但台词相同也不自动代表试片可以直接入正片。

具体作品的角色、截图、故事事实和改写文本留在项目。只有来源核验、改编与审查方法回写 Skill。
