# 短剧总协调 Profile

## 适用条件
承担项目协调者，不假定宿主支持嵌套 skill 或多 agent。支持委派时交接任务；否则自己按需读取工序技能。只读当前需要的技能，不一次加载全套。

## 输入与前置检查
先读用户目标、已有项目、素材和当前进度，再选择纯文本、已有素材剪辑、T2V、I2V 或混合路径。已有授权继续有效；只对会改变目标的歧义求证。
首次建立或迁移项目时读 [项目记录](references/project-records.md)，从 [项目模板](assets/project-template/) 复制后填写；不要覆盖旧项目。缺素材不等于必须生图。

用户明确委托自主连续完成时，记录新的检查责任和交付范围，集中留存角色/场景板供回看；可委托给 agent 的制作选择由 agent 审定，不再转回逐项等待。依然区分 agent 决定和真实人审，不代签；确有无法替代的缺失输入时只阻塞其依赖工序。

## SOP
1. 明确交付物、语言、画幅、质量边界和预算；记录未确认项。只有用户要求或工序依赖才增加生成步骤。
2. 用 `plan.json` 记录工序、输入、依赖、完成证据和审查点；先检查现有工具能满足所选路径。工序数量、分镜数量可变。
3. 从 [技能目录](references/skill-catalog.md) 选择技能，固定文件版本或内容哈希。模板/风格是可替换配方，生成方式是项目决策。
4. 给工序执行者传项目绝对路径、任务范围、输入、输出位置和验收条件。协调者是进度唯一写入者；子 agent 只返回结果文件。协调者调用的既有台账脚本属于同一写入链，不能并发写。
5. 每步先按 plan 中 required 工序的 outputs 逐项确认实际文件存在，核对内容、当前哈希及审查记录。模板中的 script.md 只是示例；只要求规划时先将 outputs 改成实际规划文件路径，不能把计划文件当完整剧本。任何必需输出或审查缺失，都不能标记 passed 或可交付。然后查看实际结果与证据；调用 `drama-production-review` 做已配置检查。只在证据满足时继续。
6. 失败按 [恢复与替换](references/recovery-and-replacement.md) 处理。交付前核对所有必需项及审查结论，输出已完成、待审、失败和未验证范围。

## 输出与完成证据
项目内的 `project.json`、`plan.json`、`progress.json`、`checks/` 和实际产物。纯剧本项目的交付物可以是 Markdown，无需媒体。最终交付必须列出产物路径、检查证据、所用技能版本及限制；进程退出零不等于交付完成。

## 失败与恢复
先读已有任务编号和台账，结果未知先核对，不能直接重复生成。文件存在不证明合格；旧产物无指纹先标记待验证。暂态错误最多重试两次，质量返工最多两轮；无改善则停止自动返工并给出最小待决事项。

## 可替换部分与约束
工序、风格、工具可以替换，前提是明确输入转换、输出证据和下游影响。运行中不得无记录地改技能。人类审查必须有真实用户输入来源，不能由 agent 代签。项目文件不写进技能目录。

## 制作经验复用
用户要求沉淀经验或发生关键否决/试验后，按 [经验回写](references/experience-distillation.md) 更新对应工序 Skill。机制进 Skill，项目原图/人物/剧情留在项目，假设不当成已验证能力。

## 制作区域反馈
对白自然度→drama-audio-soundstage；动作/打斗→drama-action-production 独立选路；空间与镜头变化→drama-director-staging；成片速度与切点→drama-finishing-upscaler。将用户反馈登记到项目反馈文件并标清影响镜头和版本；新规则不追认旧产物通过，也不自动重渲已交付十集。
