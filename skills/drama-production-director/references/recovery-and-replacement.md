# 恢复与技能替换 SOP

## 恢复
1. 读取进度、任务编号、工作流快照与最新产物证据。
2. 有外部编号先查对应任务；超时可能已提交，未知状态写 blocked/reconcile_external_job。不要换 seed 重投来“解决”回执丢失。
3. 对已完成文件检查哈希、完整性和上游指纹。大小阈值只能发现明显坏文件，不能作为复用依据。
4. 输入变化，标记对应工序及下游失效；保留旧版本。混音变化不重跑视频。
5. 前置检查失败只修改相关输入；禁止删掉失败镜头后宣布全集完成。
6. 暂态错误最多重试两次；每次记录原因。质量最多返工两轮，记录 fixed、residual、new_issues，连续无改善则停止自动重试。

## 替换
候选先登记 skill 名称、源 URL/路径、版本/哈希、许可证、工具依赖与输入输出差异。阅读候选说明和脚本后在隔离案例试用；不直接覆盖安装目录。
同一案例比较基线和候选的实际产物、审查结果及成本。风格变化不应被当成技术失败；未满足用户目标则不能激活。
激活时更新项目的 selected_skills，保留原版本与回滚位置；写明哪些已产物需要重做。运行中的任务继续使用启动时快照。回滚恢复旧技能选择，不删除新版本证据。
外部 skill 无同名输入时，先在交接说明中映射字段和归档位置；反复出错才写转换脚本。禁止为预期兼容而先造通用平台。

## 典型失效边界
- 台词/镜头事件改变：分镜对应提示词、渲染、声音、交付失效。
- BGM 或降噪参数改变：声音与交付失效，原始视频可复用。
- 首帧改变：对应渲染及下游失效；不影响无依赖的其他镜头。
- 审查策略改变：重新审查；不自动重新生成全部媒体。


保留旧状态不等于已验证可复用：无真实产物或哈希时，记录 preserved_state 与 reuse_verified=false。只有本地历史快照而没有服务端点时，可以继续核对原编号，但不能把快照当作当前服务证明。缺少原始提示词时先记录配置变化，内容制作保持 pending，不编造完成。

单镜风格覆盖写入该 seg 的配方路径/版本和输入文件，而不是修改全项目 selected_skills；否则应按全局技能变更处理。可执行文本替换演练见仓库 examples/skill-replacement。
