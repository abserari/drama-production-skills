# 制作经验回写 Skill

用户要求将制作经验复用时，在制作过程中维护项目 `reports/experience-log.md`，关键否决、实验和验收后更新，不等项目结束才凭记忆总结。

每条记录：触发问题、原证据/产物版本、修正动作、实际结果、可迁移规则、适用范围、验证状态。区分“用户偏好”“已验证机制”“本机条件”“待验证假设”。

回写规则：
1. 把身份核实、参考用途、人审边界、低清筛选、精修准入、失败恢复等可迁移步骤放入对应工序 Skill 的 references，并从入口链接。
2. 项目人物、剧情、原图、具体色卡、机位、seed、当次账目和来源 URL 保留项目内，不将它们变成下一部剧的默认值。
3. 不把单次成功、传闻或估算写成保证；注明经何种样本验证和仍未知的边界。用户否决的旧做法保留原因，避免下一次又犯。
4. 只在证据表明反复出错或确定性保障必要时补小工具，不为每个偏好新增代码或统一工程入口。
5. 更新维护源后检查本地链接与模板，发布到安装副本并检查一致；正在运行的任务保留启动时规则/参数快照，后续任务再采用更新。

最终交付列出：本次改了哪些 Skill、依据、验证与未验证项、项目记录位置。读者应能换剧本、换角色和工具后沿用机制，而非复刻这一部作品的细节。
