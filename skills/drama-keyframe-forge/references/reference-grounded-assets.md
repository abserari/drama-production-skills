# 有来源的参考驱动资产：人物、场景、道具

适用：改编指定作品、用户要求参照网络原图、已有候选被否决或必须保持既有角色身份时。原创自由设计无需强制查网。

## 先核实对象，再生成
1. 先确认具体角色、作品版本、场所和关键道具；不能凭名字或印象补造外观。
2. 优先采用用户指定原图、官方设定/发行素材、可识别的游戏或影视原始画面；社区截图、Wiki、二创分开标注。官方页面中的其他角色也可能与本项目无关。
3. 实际查看每张图，核对姓名/UI、发色、轮廓、服装、身体或物种特征。不要把搜索引擎自动图注当事实。截图右侧 NPC、另一条剧情线的老板、早期版本造型不可无条件混用。
4. 项目内保留 raw 原图和来源清单：id、source_page、asset_url、获取日期、文件路径、sha256、版本/上下文、reference_scope、selected/排除原因。来源归属不等于使用授权；不据下载成功推断许可。
5. 旧剧本与参考冲突时，先在项目里列出冲突和受影响产物；旧描述不再作为外观事实。保留原文件，等待改编决策，不静默把新图改回错误旧描述。

## 三要素分别定案
|对象|锁定内容|不确定部分|
|---|---|---|
|人物|脸与轮廓、发色/头饰、服装色块、左右侧护甲/义体、可见物种特征|未见背面、下半身、遮挡特征必须标记推定，不能称原设|
|场景|地面与材质、门/柜台/楼梯的相对位置、光源、活动空间、轴线|截图看不见的区域是制作重建，须单独审查布局|
|道具|形状、颜色、数量、尺寸比例、握持方式、归属角色|细节放大视图不是额外实物；不能让一张双视图卡变成两个人或多把武器|

每次生成写清每张参考的用途与禁止继承内容：身份、风格、空间、道具、构图分别说明；参考图中只借用指定角色，不把 UI、对白框、无关人物或原构图一起复制。

## 生成与检查
- 风格选择、角色身份、场景布局、道具设计是不同决定。用户选了某种画风，不等于批准该图全部内容。
- 用当前可用生图工具进行有参考生成；保存原始提示词、实际参考路径/哈希、工具、候选版本和产物哈希。不能把只下载参考说成已经按参考生成。
- 人物卡、场景图、道具卡独立检查后，再合成每个分镜的单一场景首帧。多视图设定卡只能作参考，不能直接作为 I2V 第一帧；首帧中人数、道具数量与机位必须符合本镜。
- 对照原图检查至少三类关键特征，列出实际偏差；身份错误先修身份，不用美观评分掩盖。缺参考或未见细节标记 unknown/重建，不伪造确认。
- 按项目设定的人审节点呈现具体候选，逐项记录通过、修改、拒绝。被拒版本保留；下游不得复用对应旧外观。

项目名称、人物姓名、原图和具体机位留在项目；这里只维护可迁移机制。不同分镜能否保持身份仍须视频验证，首帧通过不是时序一致性保证。

## 资产批准不等于镜头批准
角色卡、场景基准和道具通过后，分别保存其人审来源与哈希。将它们用于新生成的单一镜头首帧时，仍检查人物数量、左右关系、面部可见性、道具位置与空间一致性。按项目人审策略批准该组合帧，不能把“角色已过”记作“所有镜头均已过”。代表性试片可只依赖已批准的核心角色；未定配角只阻塞真正依赖它的后续镜头。
