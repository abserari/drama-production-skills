# 声音管线手册 v3 —— 对白保留 / 动作拟音保留 / 持续床音清零

> 这份文档回答一个问题：**为什么逐段生成的片子拼起来"配音不连续"，以及怎么治。**
> 提示词写法见 `prompt_standard_v2.md` 第四节；这份只管「判据、命令、调参、验收」。

---

## 一、断层的根因（已量化，不要再猜）

对旧版 28 段成片做逐段音轨分析（`scripts/diagnose_audio.py`）：

| 指标 | 实测 | 含义 |
|---|---|---|
| 语声 F0 变异系数 | **34.7%** | 同一角色跨段音色漂移（声线卡没锁住） |
| 段间接缝能量落差 >6 倍 | **11 / 28 处**（最大 121 倍） | 接缝两侧"底噪"对不上 |
| 段尾 250ms 能量异常 | 多段偏高 | 台词或拟音被尾部截断 |

结论链：
1. 每段独立生成，H3 会给每段**自配一套环境床音**（风声 / 沙粒持续摩擦 / 空间混响 / 47Hz 谐波音乐垫）。
2. 床音是**连续存在**的，接缝两侧两套床音不可能对得上 → 耳朵立刻听出剪辑。
3. 拟音（脚步、珠子落槽）是**段内点状事件**，在段内起止，接缝两边本来就该安静 → 不构成断层。
4. 所以：**只清持续床音，不要清拟音**。全静音会让画面"假"（旧 v2 方案的错）。

## 二、三层判据

| 层 | 识别特征 | 提示词层 | 后处理层 | 验收 |
|---|---|---|---|---|
| 对白 | ≥0.55s 的连续语声事件 | `<Audio N>` 声线卡 + `<d>` 台词 | 原样保留（低过减） | 结束点距段末 ≥1.0s |
| 动作拟音 | 高出床音 10dB、<0.55s 的短事件 | 每拍 `音效：` 逐条点名 + `仅此 N 类` 封口 | 保留（SNR 自适应，轻减） | 每段 ≥1 个（`--fx yes`） |
| 持续床音 | 每个频点都在响（时间低分位可见） | `overall_soundscape` ③数字静音 + 禁止清单 | `audio_gate.py` 清零 | ≤ **-50 dBFS** |

**段尾留白**：最后一个事件到段末 ≥0.35s —— 否则拼接时最后一帧拟音被硬切。

## 三、命令（全部用 venv python）

日常生产**不需要手敲音频命令**，`sop_run.py watch` 与 `h3proj.py finish` 已经把下面这些串起来了。
这一节留着手动排障用。

```bash
PY="C:/Users/windows/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
cd <skill目录>/scripts

# 1) 一采落盘后立刻自检（正式流程里由 sop_run.py watch 自动做）
$PY check_audio_seg.py --latest --fx yes

# 2) 指定文件 / 指定声线卡
$PY check_audio_seg.py --file "<一采 mp4 路径>" --card S1 --fx yes

# 3) 只出音轨（交付流程里 finish 的第一步就是它）
$PY audio_gate.py --in "<终片或上游成片>" --out seg13.wav --audio-only

# 4) 清完复检（床音应落到 -70dBFS 以下）
$PY check_audio_seg.py --file "<交付片>" --fx yes

# 5) 局部/全片连续性复盘（--dir 与 --order 为必需参数）
$PY diagnose_audio.py --dir "<成片目录>" --order order.txt --tmp <tmp> --out seam.json
#    order.txt 一行一个段名（不带扩展名，按拼接顺序）
```

**音轨从哪来，由 `finish` 自己判断**，不要写死"二采 N304"：

1. 终片自带音轨 → 用它。
2. 终片无音轨 → 从 `sop_run.py final` 记录的候选中挑：优先成片源前缀（`wf_map.roles.prefinal`），
   其次任一带音轨的上游产物。
3. 你确实想指定 → `h3proj.py finish --seg seg01 --audio-from <路径>`。

**实测（1018 链路）：超分出来的 1080p 文件是无声的**，即使超分节点「保留原音 = 开」。
它的「视频」输入接的是合成节点的「🎬视频透传」，图像编码模式下那个口恒为 `None`，
音轨根本没带过来。所以 `finish` 会走第 2 条，从三采（prefinal）取音轨 mux 到 1080p 画面上 ——
这不是降级，是这条链路唯一正确的取法。

> 为什么不能写死二采：一采→二采→三采 的链路上，二采音轨和三采音轨不是同一路声音，
> 拿二采的去 mux 三采画面 = 白丢一档质量，还可能音画不同步。

## 四、`audio_gate.py` 调参

原理：**先用能量最低的 `--frame-sel`% 帧估床音谱（这些帧里对白/拟音基本不出现），取每频点中位数；帧数不足时回退到每频点 `--bed-q` 低分位**。然后逐时频点按 SNR 过减 —— 接近床音的狠减（alpha-bed），显著高于床音的轻减（alpha-fx，保护对白与瞬态）。

| 参数 | 默认 | 作用 | 什么时候动 |
|---|---|---|---|
| `--frame-sel` | 40 | 用「能量最低的 40% 帧」估床音谱 | 台词密集段被削 → 调小（30）；床音估不准 → 调大（50） |
| `--alpha-bed` | 6.0 | 床音过减因子 | 床音残留 → 调大（8-10）；拟音发虚 → 调小（4） |
| `--alpha-fx` | 1.0 | 对白/拟音过减因子 | 台词有"水下感/金属声" → 降到 0.6 |
| `--fx-snr` | 4.0 | 帧级"整帧无内容"阈值 | 静音段有残留 → 调大（5-6）；静音段被削掉呼吸 → 调小（3） |
| `--quiet-gain` | 0.03 | 判定为静音帧的增益 | 数字静音不够彻底 → 调到 **0.005**（不要 0，避免绝对零造成突兀）。默认 0.03 有副作用，见下方警告 |

> **⚠️ `--quiet-gain` 太大会把台词结束点往后顶（有对白段实测）**
>
> 用默认 0.03 清床音：床音从 −29.5 清到 −52.4（清得很成功），但清理后**凭空冒出一段低电平内容被判成语声**，
> 台词结束点从 **5.09s 跳到 6.35s**，差 0.08s 不过闸门。原因是 `quiet-gain` 把清完后残留的微小声放大了。
> 降到 **0.005** 配 `--fx-snr 6` 后直接 PASS。
>
> **有对白段的实测可用全参**：
> ```bash
> $PY scripts/h3proj.py finish --seg seg09 --frame-sel 55 --alpha-bed 8 --quiet-gain 0.005 --fx-snr 6
> ```
> 清床音实测：−29.5→−76.1 / −36.0→−56.3 / −48.7→−80.2 / −50.0→−97.5。
>
> **推论：判定 F0 / 台词结束点之前必须先清床音。** 未清时测出的数值都不可信——
> 实测同一段语声清前 F0 **171Hz**（像是人声跑偏到声线卡 130Hz 之外）、清后 **125Hz**，正好落在 130±35 内。
> 别拿到原始值就重抽。

**改任何参数后必须跑回归**：

```bash
$PY test_audio_gate.py
```

合成信号 = 47Hz 谐波垫（冒充音乐垫）+ 低通风声 + 脚步 + 珠声 + 语声。判据：床音清到 < -100dBFS，瞬态跌幅 < 2dB。

> 历史教训：v3 第一版把 `alpha_bed` 设得过大 + 用全局分位估床音，真实素材上拟音峰值掉了 18dB（听感"被抽空"）。是合成回归测试定位到的，不是耳朵。

### 源头床音很响时的实测配方（20261019）

拿一段旧写法的三采（源头床音 **-26.9 dBFS**）扫参数：

| frame-sel | alpha-bed | 处理后床音 | 结论 |
|---|---|---|---|
| 15 / 25 | 6 / 10 | **-27.9 ~ -28.5** | 几乎没压 —— 低能量帧里本来就没床音，估出来的谱接近 0 |
| 40（默认） | 6 | -40.2 | 不够 |
| 55 | 6~8 | **-48 ~ -53** | 可用；拟音仍在 |
| 70 / 85 / 95 | 6 | -40.8 / -37.4 / -36.9 | 又开始被对白污染，反而变差 |

结论：**默认 40 不是普适最优**，床音越"铺满全段"越要把 `frame-sel` 往 55 提。
`finish` 已经把这几档参数透传出来了，不用再手敲音频命令：

```bash
$PY h3proj.py finish --seg seg01 --frame-sel 55 --alpha-bed 8
```

同一条素材：默认参数判 FAIL（-41.3），`fs=55 α=8` 判 PASS（-53.3，拟音 1 个仍在）。
先调参数再谈重抽；调到 `fs=55 α=10` 还过不了，才是源段该重抽（提示词里补
「数字静音 + 禁止风声/混响/音乐垫」）。

## 五、提示词层能做到多少（实测）

seg13 v2.1（seed 1477206148，第 4 次重抽才全项通过）：

| 阶段 | 床音电平 |
|---|---|
| 旧写法「音效：无（后期添加）」 | -39.3 dBFS |
| 新写法（三层点名 + 禁止清单） | -50.6 ~ -51.3 dBFS（已达门限） |
| 再过 `audio_gate.py` | **-76.7 dBFS** |
| 拟音代价 | 峰值损失 0.3dB（3 个拟音全部保留） |

**要点**：提示词能把床音压到门限附近，但压不到"绝对没有"。所以**提示词 + 后处理两道都要**：
提示词少生成 → 后处理少伤拟音；提示词完全不管 → 后处理要狠减，拟音必被削。

**反面写法（v2 踩过）**：`音效：无（后期添加）` —— 模型学到的是"这里没有声音"，结果是
既没生成该有的珠子声，也没少生成风声。正确写法是**逐条点名 + 封口**。

## 六、全片生成顺序

```
逐段：submit（preflight 内置）→ watch（视觉定量 + 音频四项，不过即 AUTO_ABORT + 换 seed）
   ↓
逐段：review（8 类视觉错误签字）→ final（等终片）→ finish（取音轨 → 清床音 → mux → 复检 → 归档）
   ↓
全片：h3proj.py concat（同分辨率 -c copy；混分辨率自动重编码）
   ↓
全片：diagnose_audio.py 复盘接缝（判据见下）
   ↓
后期：统一铺 BGM（此时整条音轨已无床音，BGM 才是唯一连续层）
```

**接缝判据（v2.2 校正）**：床音清零后，接缝两侧本来就是数字静音，**能量比值会被分母趋零放大**（实测 20000:1 而听感完全正常），比值不能当判据。改为：

| 检查 | 通过标准 |
|---|---|
| 两侧绝对电平 | 前 100ms 与后 100ms RMS 均 < -50 dBFS |
| 比值（仅在两侧都 >-50dBFS 时看） | < 6 倍 |
| 跨接缝尾巴 | 段尾 100ms 内无 >0.3s 的持续非静音 |
| F0 一致性 | **同角色内部分组**计算，CV <10%；跨角色混算无意义 |
| 人耳 | 无咔哒、无音量跳变、无半句台词 |

拼接：

```bash
ffmpeg -f concat -safe 0 -i list.txt -c copy 全片.mp4
```

**有对白的片子不能这样一把拼——音频要和视频按同一个头部裁剪量对齐。**

视频侧按 `trim_frames` 裁头（承接帧要丢掉），音频也必须按**同一时刻**裁，否则台词的嘴型会错位。
两种片子的拼法完全不同：

| 片子类型 | 音频拼法 |
|---|---|
| **无对白** | 整条铺数字静音（第一幕就是），不需要对齐 |
| **有对白** | **绝不能整条铺静音**（四句台词会全丢）。逐段 `atrim` 后 `concat` |

```python
# 逐段：视频裁头 trim 帧，音频也从同一时刻开始
for seg, p, trim, info in items:
    t = trim / FPS          # FPS = 24
    if info["audio"]:
        af = "atrim=start=%.6f,asetpts=PTS-STARTPTS,aresample=48000" % t
```

**验收方式**：拼完用 `check_audio_seg.py` 逐段复验，有台词的段应各检出 **1 个语声事件**。
第二幕四句台词就是这么逐个确认"真的在片里"的——只看画面容易被"口型对了但没声音"骗过去。

- 插帧开不开都要**所有段同帧率同编码**才能 `-c copy`：RIFE 输出 48fps，关掉插帧是 24fps。
  混着来就统一重编一次。
- 拼接后音频若出现 1 帧咔哒，用 `-af "afade=t=in:st=0:d=0.01"` 段内处理，不要全局降噪（会重新引入床音）。

## 七、已知极限（别浪费时间对抗）

1. **台词落点不受控**：H3 对"约 5.4-7.6 秒"这类秒数不敏感。seg13 四次重抽里 2 次把末句拖到 9.7s 贴尾。
   → 靠自检筛选 + 换 seed，不靠改指令。末句尽量放节拍中段。
2. **H3 会跟画面自动补拟音**，有时补多（比如凭空加水声）。→ 自检里统计但不惩罚，人工听感为准。
3. **47Hz 谐波音乐垫**是 H3 的默认习惯（"电影感"），提示词只能削弱不能根除，必须靠 gate。
4. **无法分轨**：对白/拟音/床音在同一条轨上烘焙。所有"只留人声"的设想都要走音频处理，不走模型。

## 八、影视级配乐融合与人声智能避让 (Audio Ducking)

> **工业铁律**：
> 1. **严禁依赖 H3 自发生成 BGM**：H3 内部合成的配乐无法分轨，跨段直接断层，且电平不可控，会严重掩盖对白。提示词必须明确声明 `禁止背景音乐/禁止BGM`；
> 2. **独立配乐外挂**：全片完成对白与动作拟音清洗（G5）后，全集拼接阶段外挂独立高保真 BGM 轨；
> 3. **人声智能避让 (Audio Ducking)**：利用 FFmpeg 原生 `sidechaincompress` 动态侧链压制滤镜，当人声说话时，BGM 瞬时下潜 -14dB (压至 20%)，台词字字清晰；台词停顿或紧张动作戏时，BGM 在 0.3-0.5s 内平滑恢复满电平！

### 8.1 侧链压制滤镜链与核心参数

```
[1:a]aloop=loop=-1:size=2e+09,volume=0.35[bgm_raw];
[bgm_raw][0:a]sidechaincompress=threshold=0.06:ratio=5.0:attack=80:release=400[ducked_bgm];
[0:a][ducked_bgm]amix=inputs=2:duration=first:dropout_transition=2:weights=1.0 1.0[out_a]
```

| 参数 | 推荐值 | 作用与原理 |
|---|---|---|
| `volume` | **0.30 ~ 0.35** | BGM 基础增益（确保静音时也不会喧宾夺主） |
| `threshold` | **0.06** (-24 dBFS) | 人声避让触发阈值，高于此电平即触发压制 |
| `ratio` | **5.0:1** | 压制比，使 BGM 下潜约 14dB（电平缩减至约 20%） |
| `attack` | **80 ms** | 快速响应人声首个辅音，防止吞字爆音 |
| `release` | **400 ms** | 句子结束后平滑过渡扬起，避免“呼吸抽吸”突兀感 |

### 8.2 工具调用

日常生产可直接调用：
```bash
python scripts/cinematic_audio_mixer.py \
  --input "成片/全片.mp4" \
  --output "成片/全片_配乐院线版.mp4" \
  --bgm "assets/bgm/theme_suspense.wav" \
  --volume 0.35
```
视频流采用 `-c:v copy` 物理直通，2-4 秒内极速交付，画质零损失。

## 九、原生自锚定声纹 (Self-Anchor Voice) 与单说话人门控 (Delroy715 实战吸纳)

> **核心问题**：多镜头切换时，不传参考音频音色必飘（第 1 段低沉、第 3 段尖细）；传外部 TTS 参考音频又有极重的“AI 朗读播音腔”，且导致后段高潮戏吼不出来。

### 9.1 原生自锚定声纹 (Self-Anchor Voice)
1. **原理**：MiniMax-H3 是原生音视频联合扩散模型（AV-DiT），H3 自身在首段原生生成的声线最具呼吸感、唇形匹配最精准、AI 味最轻；
2. **提取母本**：在第 1 段生成完成后，若听感自然，使用 ffmpeg 从该段无损剥离出对白语音：
   ```bash
   ffmpeg -i seg01.mp4 -af "aresample=32000,pan=stereo|c0=c0|c1=c0" -vn native_lead_seed_stereo.wav
   ```
3. **后续全段锚定**：将这枚由 H3 自己发出的原生声音切成 3~5 秒片段，作为全剧后续镜头的 `<Audio 1>` 声纹参考卡。既 100% 锁死音色，又完全杜绝外部 TTS 的机械念稿腔！

### 9.2 按段单说话人门控 (Speech-Active Gating)
- **严禁多声纹交叉污染**：在同一段落的执行图中，**严禁同时连接男女主角的两路参考音频 `<Audio 1>`, `<Audio 2>`**！全序列多头交叉注意力会引发双声纹干扰，导致不说话的人抢话或男女声串音；
- **门控法则**：遵循“谁在这一段开口，这一段的执行图就只挂谁的 1 路参考音频”。对峙戏中角色 A 发言段只传 A 的声纹，角色 B 发言段只传 B 的声纹。
