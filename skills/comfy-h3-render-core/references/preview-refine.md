# 一采筛选 → 验收 → 二采或超分

适用：用户希望降低反复抽取成本，或需要先验证内容再投入高分辨率精修时。这里定义工序与证据，不保证任何固定分辨率或二采算法已适配。

## 一采
- 根据实际模型、节点和显存选择低成本候选，例如约 360p 与 480p。先检查合法尺寸、帧数网格及真实画幅，不能将 360/720/1080 标签直接当可提交参数。
- 用同一已确认首帧、提示词、帧数、种子和模型作短试片对比，记录实际参数、加载/采样/解码/总耗时及显存观测。模型加载和文本编码有固定成本，像素减少不意味着总耗时等比例减少。
- 一采重点检查人物与数量、台词/说话者、动作因果、场景连续性、关键道具和时长。低清看不清的五官细节标记不确定，用少量精修样本核验，不能一律当身份错误重抽。
- 明确错词、错人、动作错误应在一采修复；超分或二采不作为绕过内容失败的办法。按项目上限重抽，记录 fixed/residual/new_issues，不无限试 seed。

## 进入精修的条件
每镜保存 `pass1` 的文件、实际输入/图指纹、任务编号、输出 sha256 和当前 QC；只有对应版本通过且满足人审要求，才进入 `pass2`。前序内容改变，旧精修与审查失效。后期配乐改变不要求重新生成原始视频。

## 比较精修路线
1. 使用同一段合格一采，比对真正的模型二采与已验证的超分路线，选择效果/耗时合理的方案，必要时按镜头类型区别处理。
2. 模型二采必须证明其实际接受一采输出或潜变量、保持原时序并做受控去噪。不能把另换 seed 的高分辨率重新生成称为二采。
3. 对音画混合、视频 5D 或特殊打包潜变量，检查真实节点实现及压缩倍率；普通图像 LatentUpscale/Concat 不能凭名字直接套用。缺少适配时标记未验证，选择可用超分或继续验证具体工作流，不伪称已支持。
4. 精修检查实际输出尺寸、帧数/时长、动作、首尾、身份、口型和闪烁；锐度分数不能代替内容与时序检查。精修导致漂移时保留一采并拒收候选。
5. 原音轨单独保留与核对。流拷贝也可能因截短参数丢掉末尾包；承诺完整保留时，比较音频包哈希或等效可验证证据，不仅检查“有音轨”。

## 轻量记录
`pass2` 至少记录 route、source_pass1_sha256、实际参数/工作流、任务编号、产物哈希、性能与检查结论。raw 产物、候选与通过版本分目录；GPU 重任务串行，恢复先核对原任务，交付前核对完整镜头与必需审查。

固定参数、成本阈值、测试素材属于项目或明确版本化配方；只有实际测过的能力才能标记 verified。一次短试片不能证明整集或所有场景都可无人值守。


## 运行状态会干扰成本比较
出现持续异常长步时，先保留当前任务与每步时序，结合模型驻留、专用/共享内存、加载与采样数据判断，不把共享内存数值单独当作故障证明。必要时只中断本任务，确认队列空闲后调整运行时显存预留或清理模型驻留，再重新测试；旧异常运行标取消/诊断，不是内容质量失败。

不同尺寸即使种子相同，潜变量噪声形状也不同，表演不保证逐帧一致。记录冷/热顺序、服务参数、每步波动与被中断尝试；一次短片只能支持该镜的暂定选型。局部本机修正有效时，不能把某个显存预留数值写成所有设备的铁律。
# 对白转写的判读边界

逐字转写只能作为对白证据的一部分。先确认该镜是否规划对白；没有对白时转写检查为不适用，环境声上的识别幻觉不能直接触发重抽。存在对白时，保存未经改写的识别文本、期望句和差异，同音字及标点差异先复核声音，不直接判错词。即使逐字匹配，也不证明声音身份、监听者闭嘴或口型正确。

双人同框的监听者不能稳定闭嘴时，先区分无声露齿笑和真正串话；项目明确要求闭嘴，则露齿笑同样不满足条件。加强负面提示或换种子没有改善时，可在不改变对白、位置和动作因果的前提下，改用已核验的反打、遮挡或画外监听构图。该方法解决的是可见嘴部约束，仍须检查声音，不代表已证明画外角色绝不发声。保存构图变更与失败样本，并计入同一返工上限，不能以换机位为名重置重试次数。

首次转写只有省略号、重复语气词或异常低匹配时，先对同一原音做一次不同解码策略的识别，例如 CPU beam search、无期望句提示和温度回退。保留两份原转录、音频/视频哈希与解码参数，不用期望台词诱导识别；复核找回目标句不等于重做了视频。数字写法和同音字单独分类。多次仍无可辨目标句才作为重点返工候选，不能将单次识别崩坏直接当生成失败。

单人对白也可能被模型加入新角色或替换为惯常的类型角色。发现后局部重做：采用已核实身份的紧凑单人首帧，明确短发/头饰/服装等稳定特征，减少空白中的可入场位置；移除与本镜无关的时间跳切、关系人物描写。整句对白保持不变，逐版本核对可见说话者与身份，不把“有音轨/能转写”当角色正确。
